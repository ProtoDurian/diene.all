# semantic-release

durian.cloud > engineering > standards > semantic-release

How releases are configured, triggered and published from one file

| Word | Means | Also called | See |
|---|---|---|---|
| conventions document | docs/developer/CommitConventions.md, generated by the releaser from release.yaml; regenerate it, never edit it by hand. |  | [release.yaml](#releaseyaml) |
| prepare hook | The release.hooks.prepare list of commands a descendant fills to stamp a version into its own files; empty here. |  | [release assets](#release-assets), [standards#descendant](../UL.md#descendant) |
| release assets | The files a release commits, listed in release.commit.assets; a write outside the list aborts the release. |  | [release.yaml](#releaseyaml) |
| release.yaml | The single source of truth for commit types, release levels, message rules, the conventions document and how a release commits and publishes. |  | [releaser](#releaser), [conventions document](#conventions-document) |
| releaser | The registry tool that reads release.yaml to lint commits, calculate versions, write the changelog and publish a release. |  | [release.yaml](#releaseyaml) |
